# 채용 공고 임시저장 배포 점검

2026-09-12. 사용자 승인 범위: Supabase 임시저장 테이블 추가, 서버 배포, GitHub 푸시, Cloudflare 운영 배포. 기존 운영 데이터 삭제 및 이메일 발송은 포함하지 않는다.

## 확인한 항목

- 기존 스타일과 인증 구조를 유지한다. 임시저장은 별도 `posting_drafts` 테이블이며 작성자 ID로 모든 조회·수정·등록을 제한한다. 관리자 예외는 없다.
- 로컬 전체 테스트 857개 통과. 빌드 성공. 이전 검사에서 린트 오류 없음, 기존 Fast Refresh 경고 3개.
- Supabase 마이그레이션 적용. RLS 활성화, anon/authenticated 역할의 SELECT 권한 없음 확인.
- 운영 API에서 미완성 입력·이모티콘·공백 저장, 재조회, 수정, 동일 요청 재시도, 오래된 수정 거절 확인.
- 비로그인 접근 401, 다른 관리자 계정의 읽기 404 및 수정·등록 409 확인. 공개 공고 목록과 상세에 초안 미노출 확인.
- 운영 API로 같은 초안을 동시에 2회 등록하여 201/409 응답 및 공개 공고 정확히 1개 확인. 등록된 초안은 임시저장 목록에서 제외됨.
- 검증용 계정·초안·공고·세션·감사 기록 정리 후 기존 계정 1개, 기존 공개 공고 1개, 초안 0개 확인. 실제 이메일 발송 없음.

## 배포 순서와 복구

테이블 추가 → 서버 배포 및 위 API 검증 → 같은 소스 GitHub 푸시 → Cloudflare 운영 배포 상태와 정적 빌드 확인 → 공개 API 점검.

임시저장 내용 누출, 저장 실패, 중복 등록 발생 시 직전 프런트/서버 배포로 복구한다. 새 테이블과 저장된 초안은 삭제하지 않는다. 스키마는 추가형으로 기존 공고 등록 경로와 호환된다.

별도 스테이징, 브라우저 조작 검증, 장시간 부하·모니터링은 이 변경에서 수행하지 않았다. 운영 API 검증과 빌드 확인을 브라우저 검증으로 간주하지 않는다.
