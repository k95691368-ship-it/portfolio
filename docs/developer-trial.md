# 개발자 권한 체험 · 1시간

## 범위와 권한

기존 화면 스타일을 유지한다. 공개 첫 화면에서 별도 체험 계정을 만들며 기존 개발자 계정으로 로그인하지 않는다. 체험 시간은 서버 발급 시점부터 3,600초이며 자동 갱신하지 않는다. 운영 공고 작성 및 기존 이메일 발송 경로를 그대로 사용한다. 이메일 수신 성공을 보장하는 모의 체험은 아니다.

`POST /api/demo/login` → 임의 ID의 체험 계정(flags=0) → `developer_trial` 세션 → 매 요청마다 서버가 만료를 검사하고 메모리에서만 관리 권한 부여 → 만료 후 인증 거부. `GET /api/me`는 만료 시각을 반환하고 화면은 남은 시간을 표시한다.

개발자 플래그 계정과 소유자 이메일 계정은 계정 목록에서 숨기고 변경·삭제·비밀번호 초기화를 차단한다. 서버 비밀키를 반환하는 API는 추가하지 않는다. 체험 계정의 비밀번호 로그인 및 변경을 차단하여 영구 세션으로 전환하지 못하게 한다.

## 데이터와 실패 처리

새 스키마 없이 기존 users/sessions를 사용한다. 실제 공고는 기존 job_postings에 저장되며 만료 시 삭제하지 않는다. 만료된 체험 계정에는 저장된 관리자 권한이 없다. 요청한 운영 데이터 보존을 위해 체험 생성 자료의 자동 삭제는 하지 않는다. 생성 실패 시 오류를 표시하며 권한 발급은 성공한 세션에 한한다.

체험 시작에는 기존 IP 기반 시간당 3회 제한을 적용한다. 여러 IP를 이용한 반복 체험은 이 제한만으로 방지할 수 없다. 실제 메일 전송을 허용하므로 공개 운영 시 기존 발송 제한과 공급자 사용량을 확인해야 한다. 사용량이 커지면 별도의 검증된 체험 신청 및 원자적 할당량 제어가 필요하다.

## 공고 편집

7개 항목의 정적 예시와 20개 이모티콘을 제공한다. 선택 위치 삽입·미리보기·실제 공고 저장을 지원한다. 표시할 때 HTML을 실행하지 않고 React 텍스트 노드로 출력한다. 예시는 실제 채용이 아님을 제목과 본문에서 명시한다.

## 검증 및 배포

- 사용자 승인: 기존 Supabase 예시 데이터 정리, 새 공고 등록, 검증 후 GitHub/Supabase/Cloudflare 배포.
- 실제 이메일 시험: 사용자 요청으로 생략. 공급자 발송 제한 해제 여부 및 실제 수신은 검증하지 않는다.
- 회귀 테스트: 1시간 만료, 갱신 금지, 계정 보호, 실제 공고 저장, 유니코드 삽입, 기존 테스트 전체.
- 배포 확인: 서버 공개 API, 체험 권한과 만료, 공고 공개 조회, Cloudflare 배포 상태.
- 롤백: 인증 오류 또는 보호 계정 변경 가능 시 체험 진입을 차단하고 직전 서버/프런트 배포로 복구한다. 사용자가 승인한 예시 삭제는 코드 롤백으로 복구되지 않는다.
