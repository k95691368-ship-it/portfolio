# 개선 작업 기록

## 1회차 — 필수 개선 (2026-09-19, 로컬 반영)

직전 회차는 진행으로 분류했다. 전체 배치와 계정·지원 관리 기능이 변경됐고 로컬 테스트 116파일/1,388개, 빌드가 통과했다. 다만 화면 검증 서버는 종료됐으며 운영 서비스와 분리된 지속 로컬 실행은 미완료였다.

현재 기준선: `npm run dev`의 `/api`는 운영 Supabase로 프록시된다. 5173·5189·4173번 포트에 실행 서버가 없고 이 기록 파일도 없었다. 목표는 운영 변경이 아닌 로컬 빌드·실행·실제 동작 확인이므로 운영 연결을 대신 사용하는 것은 범위에 맞지 않는다.

선정 항목은 2개다. 첫째, 실제 서버 라우트와 PostgreSQL 호환 로컬 DB·첨부 저장소·외부 발송 없는 메일함을 연결한 로컬 실행을 만든다. 단순 정적 미리보기/목업은 저장·권한·메일 링크 흐름을 증명하지 못하므로 제외했다. 둘째, 가입 인증→로그인→공고→지원→접수 복구/수정/철회 흐름을 HTTP 및 실제 화면에서 확인하고 발견한 회귀를 수정한다. 브라우저만으로 반복하거나 운영 API를 호출하는 검증은 제외했다.

검증 계획: 실제 마이그레이션 적용/재시작/롤백, 경로 탈출·다른 출처·외부 요청 차단, 업로드 다운로드 바이트 일치, 계정/공고/지원 흐름의 실제 라우트 실행, 브라우저 조작, 전체 회귀 테스트·린트·로컬 빌드·접속 확인. 운영 메일 도착·외부 AI·외부 장치 통화는 로컬 검증으로 완료 처리하지 않는다.

진행: 실제 마이그레이션을 적용하는 PGlite 어댑터, 파일 저장소, 로컬 메일함, 루프백 전용 HTTP 서버, 외부 요청을 차단하는 로컬 빌드를 구현했다. 기본 dev/preview는 운영 프록시 대신 이 로컬 서버를 실행한다. 운영 데이터·시크릿은 읽지 않는다. 중복 실행 방지는 Windows named pipe를 실제 열어 배타성을 확인했다.

중간 검증: `npm run build:local` 성공(프런트 385모듈/API 101라우트). `npx vitest run tests/localRuntime.test.js tests/localLock.test.js tests/localDatabase.test.js tests/localStorage.test.js` 4파일/25개 통과(7.29초). 실제 HTTP 가입→로컬 메일 확인→로그인 유지→비밀번호 복구·기존 세션 해제, 공고 생성→PDF 제출·동일 바이트 다운로드→접수 복구→메일 소유 증명→수정→철회, 재시작 후 보존, 다른 출처·Host·경로 접근 차단을 실행했다. 초기 테스트 기대값 2개(복구 요청 202, 비로그인 /me 200+user:null)는 기존 계약에 맞춰 수정했다. 이 수치는 테스트 실행 시간이며 업무 시간 절약 수치가 아니다.

추가 변경: 실제 계약서 보관에서 사용되는 `text/html; charset=utf-8` MIME 매개변수를 로컬 저장소가 수용하도록 수정했다. 녹화 파일 부분 읽기는 호출부의 중첩 `range` 형식과 기존 평면 형식을 모두 검증하고, Supabase 어댑터는 공급자의 206·Content-Range·길이를 확인한다. 모의 공급자 테스트로 확인했으며 운영 저장소에는 반영하지 않았다. 오프라인 HTML의 외부 preconnect/DNS 힌트를 제거하고 미등록 HEAD 경로의 자체 fetch를 404 응답으로 바꿨다.

추가 검증: 실제 브라우저에서 체험 계정→공고 임시저장→게시→PDF 지원→접수번호→로컬 메일 소유 확인→지원서 수정을 실행했다. 1,440px 채용 관리 2열과 390px 지원 수정 1열을 확인했고 모바일 문서 너비 375px로 가로 넘침이 없었다. 모바일 메뉴 열기/닫기는 확인했다. 지원 철회 확인창 호출 시 브라우저 제어 응답이 멈춰 해당 화면 검증은 완료하지 못하고 임시 탭을 닫았다. 철회·오래된 수정 거부·재시작 보존은 실제 HTTP 테스트로 확인했다.

회귀 결과(14:12): `npm test` 120파일/1,438개 통과, 26.32초. 기본 샌드박스에서는 Vite 하위 프로세스가 EPERM으로 차단되어 승인된 로컬 테스트 권한으로 실행했다. `npm run lint` 오류 0, 기존 Fast Refresh 경고 3개. 계약서 보관은 실제 보관 함수와 PostgreSQL/파일 저장소를 연결해 실행했다. 시간은 검증 실행 시간이며 업무 절약 수치가 아니다.

로컬 반영: `npm run build` 성공(385모듈·API 101라우트·보관 작업 번들). `npm run local`로 최신 오프라인 빌드와 서버를 실행했다. `http://127.0.0.1:5173` HTTP 200, `/__local/health` 실제 라우트 101개·마이그레이션 8개 적용/원격 예약 1개 제외, `/api/jobs` 빈 목록을 확인했다. 새 브라우저에서 홈→공고와 모바일 메뉴→지원 현황 이동을 실행했다. 390px에서 문서 너비 390px, 이동 후 메뉴 닫힘을 확인했다. 외부 네트워크 힌트는 없고 connect-src는 self다.

정리: 5189 검증 서버를 종료하고 임시 DB·파일·메일 디렉터리, 검증 PDF·서버 헬퍼 및 배포용 임시 번들을 제거했다. 5173 서버의 빈 로컬 데이터는 유지했다. viewport 임시 변경은 원복했다. 삭제한 것은 이번 작업의 일회성 검증 데이터이며 운영 데이터는 삭제하지 않았다.

미검증: 브라우저 지원 철회 확인창 이후, 운영 메일·외부 AI·장치 통화·실제 Supabase 부분 읽기. 현재 한도 조회상 일반 사용 가능, 주간 잔여 49%; 초기화 크레딧은 사용하지 않았다.

다음: 구현→격리 검증→로컬 서버 실행 유지→검증용 데이터 정리→후속 필수 개선 점검. 푸시·클라우드 배포·운영 DB 변경은 범위 밖이다.

## 2회차 — 필수 개선 (2026-09-19, 로컬 반영)

기준선: 일회성 5189 서버에 가상 공고/지원서를 만들고, 지원서 이름 입력→왼쪽 지원 현황 메뉴→브라우저 뒤로 가기를 실행했다. 확인창 없이 이동되었고 돌아온 이름 입력은 0자였다. ApplyPage의 이탈 확인은 자체 뒤로 링크와 탭 종료에만 걸려 있으며 RecruitPage·ApplicationManagePage·ContractPage에는 페이지 이탈 보호가 없다.

선정은 최대 5개다. (1) 작성/수정 화면의 미저장 입력 이탈 보호(위험 4·영향 4·노력 3, 우선 24), (2) 지원서 저장 오류에서 입력과 첨부 재시도 상태의 정확성(4·4·2, 우선 32), (3) 긴 공고 제목의 줄바꿈, (4) 반폭 임금카드 입력 공간, (5) 모바일 메뉴 이동 후 키보드 초점. 3~5번은 코드 기반 후보이며 실제 재현한 경우만 수정한다. 읽기 전용 리뷰와 부모의 브라우저 재현을 분리했다.

대안 검토: 링크마다 클릭 방어를 추가하면 브라우저 뒤로/앞으로·프로그램 이동을 놓친다. 히스토리 임의 패치보다 설치된 React Router의 정식 useBlocker와 DataRouter를 사용하고, 탭 종료/새로고침은 beforeunload로 분리한다. 입력 데이터 자체는 브라우저 영구 저장소에 넣지 않는다. 기존 흰색·Microsoft 스타일과 업무 권한은 유지한다. 검증은 동일한 이탈 시나리오의 취소/확정, 저장 후 해제, 뒤로/앞으로, 모바일, 실제 서버 실패 및 전체 회귀로 한다.

재현 및 변경: 120자 공고명을 표시한 320px 화면의 문서 너비가 1,823px였다. 공고 카드 최소 트랙과 긴 텍스트 줄바꿈을 수정한 뒤 같은 화면의 문서 너비는 305px(스크롤바 제외)이고 상세·지원 화면에도 가로 넘침이 없었다. 1,024px 계약서 반폭 임금카드에서 금액 입력칸이 39.8px였으며, 해당 편집 카드만 전체 폭으로 바꾼 뒤 131.9px였다. 모바일 메뉴 이동 후 초점은 기존 BODY에서 main으로 이동한다. 확인 취소 시 메뉴는 열린 채 해당 링크로 초점이 복귀한다.

중간 검증: 탐색 보호·지원서 입력·레이아웃 5파일 39개 테스트 통과(0.91초), 로컬 빌드 387모듈/API 101라우트 성공, 린트 오류 0/기존 경고 3개. 실제 브라우저에서 계약 조건 이탈 취소/폐기, 지원서 Back 차단, 지원서 수정 Forward 차단, 메뉴 이동 취소/확정, 공고 임시저장 후 이탈 해제를 실행했다. 서버 400 동의 검증 오류 후 자기소개가 그대로 남았고, 동의 보완 저장→다른 페이지→돌아와 재조회한 내용도 유지됐다. 같은 지원서 다시 열기는 이제 폐기 확인이 뜬다. 불확정 응답/첨부 재전송 방지는 별도 4파일 56개 회귀 테스트로 확인했으며 브라우저 네트워크 장애 주입은 하지 않았다.

후속 확인: 독립 리뷰에서 계약 조건 저장 중 추가 입력이 성공 응답 때 덮이는 동일 종류의 입력 유실을 찾았다. 요청 스냅샷 기준 저장 판정과 지연 응답 회귀를 추가한 뒤 전체 검사를 진행한다. 아직 2회차 최종 로컬 반영·임시 데이터 정리 전이다.

추가 재현: 1,440px 채용 관리의 임시저장 표는 526px 카드 안에서 너비 900px였고 불러오기 버튼의 x좌표가 1,577px로 화면 밖이었다. 게시 공고와 같은 줄바꿈 카드 구조로 통일했다. 전체 검사 1차는 123파일 중 122파일 통과/계약 저장 재현 테스트 2개 실패(1,458개 통과, 43.33초)였으며 해당 실패를 수정 중이다. 초기 로그인 상태 조회의 guest→복원 계정 변경도 공개 입력을 초기화한다는 리뷰를 받아, 최초 복원과 실제 계정 변경을 구분하는 회귀를 함께 추가한다. 이는 미저장 입력 보호의 동일 문제이며 새 기능 확대가 아니다.

최종 변경: 계약 저장은 제출 시점 스냅샷만 저장된 것으로 판정하고 요청 중 추가 입력은 보존한다. 최초 로그인 복원은 공개 폼을 재생성하지 않으며 이후 실제 계정 전환·로그아웃은 별도 sessionEpoch로 초기화한다. 임시저장 카드의 열기 버튼은 같은 1,440px 화면에서 x=912.8~987.8px 안에 들어왔다. 실제 계약 조건 저장→공고 이동→Back→재조회에서 기본급 2,500,000원과 업무 내용이 보존됐고 저장 후 이탈 경고는 해제됐다.

최종 검증: `npm test` 124파일/1,480개 통과(29.06초), `npm run lint` 오류 0/기존 경고 3개, 일반 빌드·오프라인 빌드 모두 성공(387모듈/API 101라우트), `git diff --check` 오류 없음. 지연 계약 저장/최초 로그인 복원은 실제 컴포넌트 제어 테스트로 검증했고 브라우저 지연 응답 주입은 하지 않았다. 운영 서비스·실제 메일·외부 장치 통화는 검증하지 않았다.

로컬 반영 및 정리: 5173 서버를 최신 빌드로 재실행하고 홈 화면에 접속했다. 5189 검증 서버와 탭을 종료하고 이 회차의 일회성 가상 DB·첨부·메일, 서버 헬퍼, 배포 임시 번들을 삭제했다. 삭제한 검증 데이터는 복구용 보관하지 않았으며 운영 데이터 및 기본 5173 로컬 DB는 보존했다. 다음은 목록 조회 실패·알 수 없는 경로·이동 시 스크롤 상태를 실제로 재현한 뒤 필요한 항목만 선정한다.

## 3회차 — 필수 개선 (2026-09-19, 로컬 반영)
